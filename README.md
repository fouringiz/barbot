# Bar-bot — спеки, стоп-лист, заявки, расходы + Mini App

Группа с топиками + Google Sheets. Без ролей — бот отвечает только внутри группы бара.

## Команды бота

| Команда | Что делает |
|---|---|
| `/spec негрони` | карточка в мл; нечёткий поиск, латиница/кириллица, опечатки |
| `/have джин лайм` | что можно собрать из этих ингредиентов (стоп-лист учитывается) |
| `/menu` | авторская линия — спеки с тегом `меню` |
| `/stop` · `/stop + лайм` · `/stop - лайм` | стоп-лист; изменения постятся в «Стоп-лист» с упавшими коктейлями |
| `/need нет горячей воды` | заявка; тип сам: поломка / оборудование / бар / расходник → пост в «Заявки» |
| `/needs` · `/done 14` | открытые заявки (длинный список разбивается на сообщения) · закрыть №14; сводка заявок в топике обновляется на месте |
| `/spent` | расходы: сегодня / 7 дней / месяц |
| `/app` | кнопка «Открыть приложение» (нужен `APP_LINK`) |
| `/reload` · `/id` · `/help` | перечитать спеки · id чата/топика · справка |

**Топик «Расходы»** — без команд: текст с суммой («лаймы 12.50») или фото чека с подписью → ✅ и строка в
листе `expenses`. Фото без суммы → ❓ «Сумма?» — ответ числом. Реплай ❌ / «удали» / «проигнорь» → запись
исключается. `#14` в тексте закрывает заявку 14. Разговор без суммы бот игнорирует, альбом = одна запись.

**Авто-посты (время Баку):** стоп-лист ежедневно 11:00; заявки старше 3 дней — пн 11:05; итог дня по расходам —
в `CLOSE_TIME`; неделя — пн 11:10; месяц + CSV — 1-го в 11:15.

## Структура

```
main.py          точка входа: бот (polling) + HTTP API в одном процессе
config.py        все переменные окружения
utils.py         norm / esc / даты / деньги
specs.py         разбор ингредиентов, нечёткий поиск, карточка
classify.py      тип заявки, категория расхода, сумма, слова-отмены
sheets.py        Google Sheets: один класс, кэш спеков, run() в тред
services.py      общая логика бота и API: post(), стоп-лист, заявки, расходы, меню гостей
bots/team.py     командный бот: роутер, хендлеры, дайджесты
api/auth.py      проверка Telegram initData + членство в группе
api/server.py    aiohttp: /api/health, /api/menu, /api/me, /api/expenses (+CORS)
docs/team/       фронт Mini App «Команда»: расходы · заявки · стоп-лист · спеки (GitHub Pages)
```

Листы таблицы создаются сами при старте: `specs` (импортируй `specs_example.csv`), `stoplist`, `needs`, `expenses`, `state` (ID постоянной сводки заявок по группе и топику), `audit` (журнал действий: кто, когда, что сделал).

## Переменные окружения

См. `.env.example`. Обязательные: `BOT_TOKEN`, `GROUP_ID`, `SHEET_ID`, `GOOGLE_CREDS_JSON`. Топики: `TOPIC_STOP`,
`TOPIC_NEEDS`, `TOPIC_SPENT` — среднее число из ссылки «Копировать ссылку» на сообщение в топике. Mini App: `WEB_ORIGIN`,
`APP_LINK`, `DEV_TOKEN`.

## API

| Метод | Путь | Доступ |
|---|---|---|
| GET | `/api/health` | все |
| GET | `/api/menu` | все — авторская линия с `available` по стоп-листу |
| GET | `/api/me` | команда |
| GET | `/api/expenses?period=day\|week\|month` | команда — итог, по категориям, записи |
| POST | `/api/expenses` `{amount, text, category?, need_id?}` | команда — запись + пост в «Расходы», закрытие заявки |
| PATCH | `/api/expenses/{id}` `{amount?, text?, category?}` | команда |
| DELETE | `/api/expenses/{id}` | команда |
| GET | `/api/needs` | команда — открытые заявки |
| POST | `/api/needs` `{text, type?}` | команда — заявка + пост в «Заявки» + сводка |
| POST | `/api/needs/{id}/close` `{amount?, text?, category?}` | команда — закрыть; с суммой — ещё и расход, нужен `Idempotency-Key` |
| GET | `/api/stop` | команда — что в стопе (с упавшими коктейлями) + все ингредиенты карты |
| POST | `/api/stop` `{item, on}` | команда — поставить/снять, пост в «Стоп-лист» |
| GET | `/api/specs` | команда — все спеки с пометкой ингредиентов в стопе |
| GET | `/api/audit?limit=50` | команда — последние действия (расходы, стоп, заявки) |

Авторизация: заголовок `X-Telegram-Init-Data` (Mini App кладёт сам); подпись проверяется токеном бота, пользователь
должен состоять в группе. Для теста без Telegram: `DEV_TOKEN` и заголовок `X-Dev-Token` (фронт: `?dev=<token>`).

`POST /api/expenses` также требует `Idempotency-Key: <UUID>`. Один ключ — одна покупка одного пользователя.
Повтор того же тела и ключа возвращает ту же запись (HTTP 200 вместо 201), даже после перезапуска; другое тело
с тем же ключом получает 409. Новый ключ нужен только для новой покупки. Ключи хранятся в строках `expenses`,
включая удалённые записи. Не удаляйте эти строки и служебные колонки вручную, если нужны безопасные повторы.

Расход, ключ и задания на уведомление/закрытие заявки записываются одним добавлением строки. Только после
этого фоновая очередь закрывает заявку и отправляет сообщение в Telegram. При сбое она повторяет работу
каждые 30 секунд и после запуска. Сбой уведомления не отменяет сохранённый расход. В API есть поля
`notification_status` (`pending`, `sent`, `cancelled`) и `need_status` (`pending`, `done`, `not_found`, `cancelled`);
у старых записей они пустые. Удалённый до обработки расход отменяет оставшиеся задания.

Mini App блокирует повторные нажатия и хранит неподтверждённую покупку вместе с ключом на устройстве,
отдельно для каждого пользователя. При потере ответа или обновлении страницы появляется кнопка
«Проверить сохранение». Она повторяет исходный запрос с тем же ключом. После подтверждения локальная
копия очищается. Записи с ожидающим уведомлением отмечены в списке, который обновляется каждые 30 секунд.

## Mini App «Команда»

Фронт — `docs/team/index.html`, статика на GitHub Pages: Settings → Pages → branch `main`, folder `/docs`.
Адрес: `https://<user>.github.io/<repo>/team/`. В файле одна настройка — константа `API` с доменом Railway.

Подключение в Telegram: @BotFather → `/newapp` → выбрать бота → название, описание, картинка 640×360 →
Web App URL = адрес фронта → короткое имя (например `app`). Ссылка `https://t.me/<bot>/app` → в `APP_LINK`.
Проверить: `/app` в группе → кнопка → открывается экран «Расходы».

## Деплой (Railway)

Старт — `python main.py` (из `Procfile`; Custom Start Command в Settings должен быть пустым или таким же).
Settings → Networking → Generate Domain (порт 8080) — адрес API. Проверка: `/api/health` → `{"ok": true}`.
Переменные — вкладка Variables; после изменения — Redeploy.

**Обновление надёжного сохранения:**
1. До merge приостановить автоматический деплой Railway для этого обновления. На время переключения
   не вносить расходы: новый frontend и старый API ещё несовместимы по CORS/ключу сохранения.
2. После merge дождаться успешного `pages build and deployment` именно для нового commit.
3. Затем вручную развернуть в Railway тот же commit, без одновременной работы старого и нового worker.
4. После готовности backend всем закрыть и снова открыть Mini App, чтобы загрузить новый frontend.

Порядок не обеспечивается самим репозиторием. Для `c7263e6` Railway сообщил о начале деплоя
18.10.2026 в 16:29:13 UTC, а Pages завершился успешно в 16:29:35 UTC: процессы запускались параллельно,
хотя Railway закончил позже. Не полагаться на длительность сборок как на гарантию порядка.

Держать **один процесс и одну реплику**: общий lock защищает выдачу ID боту и API внутри этого процесса;
Google Sheets не предоставляет межпроцессную уникальность ключей. Rolling deployment с двумя
одновременно работающими workers не поддерживается.

При запуске проверяются первые десять стандартных заголовков `expenses`. Недостающие служебные поля
`request_key`, `request_hash`, `notification_status`, `need_status` добавляются в конец после любых
пользовательских колонок. Существующие строки и заметки сохраняются; чтение и запись находят поля
по именам, включая колонки, вставленные после запуска. Ошибка в первых десяти заголовках или
дублирование служебного имени даёт сообщение с конкретной причиной вместо перезаписи данных.
Старый frontend без ключа получит 400 с просьбой обновить приложение.

Очередь гарантирует повторные попытки доставки, но не «ровно одно» сообщение в Telegram: если Telegram
принял сообщение, а ответ потерялся до записи его ID в Sheets, уведомление может повториться. Номер
расхода в сообщении помогает распознать повтор; сама покупка повторно не записывается.

## Проверки сохранения без внешних сервисов

Установить `requirements.txt` в отдельное окружение Python 3.11+, затем:

```sh
python -m unittest discover -s tests -p "test_*.py" -v
node --test tests/test_expense_ui.cjs
```

Проверки покрывают конкурирующие записи бота/API, повторные запросы, потерю ответа Sheets,
очередь после рестарта, сбой Telegram, отмену заданий при удалении, валидацию API и восстановление
покупки в интерфейсе после обновления страницы. Они не обращаются к рабочим Telegram/Google Sheets.
Проверки `test_needs.py` и `test_classification.py` проверяют форматирование списка, восстановление
постоянной сводки и типизацию заявок без обращения к Telegram или Google Sheets.
`test_team_api.py` — роуты стопа, заявок и спеков, включая идемпотентное «Закрыл + расход».
Отдельный запуск: `PYTHONPATH=tests python -m unittest test_needs test_classification -q`.

## Журнал действий

Каждое добавление, правка и удаление расхода, постановка/снятие стопа, создание/закрытие заявки пишется в лист
`audit`: `at · who · action · entity · entity_id · before · after · source` (`app` — из приложения, `topic`/`bot` — из
Telegram). У удалённого расхода в колонке `deleted` стоит «Имя · дата» вместо «да». Удаление и правка из приложения
дополнительно постятся в «Расходы» (🗑 / ✏️); в приложении на экране «Расходы» внизу — «Журнал действий».
Итог дня перечисляет удалённые за день записи с именами.

## Как расширять
- Новый коктейль — строка в `specs`, потом `/reload`.
- Ключевые слова типов заявок и категорий расходов — `classify.py`.
- Время рассылок — `register_jobs()` в `bots/team.py`.
- Новый экран приложения = новые функции в `services.py` + роуты в `api/server.py` + файл в `docs/`.
